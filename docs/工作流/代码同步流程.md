# 代码同步流程

这份文档用于记录当前仓库后续的稳定更新方式。

当前远程约定：

- `origin`：自己的 fork，`https://github.com/sewth/ainovel-cli.git`
- `upstream`：官方仓库，`https://github.com/voocel/ainovel-cli.git`

当前开发约定：

- `main`：尽量保持接近官方最新版
- `feature/local-compat`：自己的长期改动分支，包含豆包兼容、本地文档等内容

## 一次性确认

先确认远程没配错：

```bash
git remote -v
```

应该看到：

- `origin -> sewth/ainovel-cli`
- `upstream -> voocel/ainovel-cli`

## 日常更新官方代码

当你想同步官方最新代码时，按下面顺序做：

```bash
git checkout main
git fetch upstream
git merge upstream/main
git push origin main
```

这四步的含义：

- 切回本地 `main`
- 从官方仓库取最新提交
- 把官方最新合进本地 `main`
- 再把更新后的 `main` 推到你自己的 fork

## 把官方最新同步到自己的功能分支

当 `main` 更新完后，再把最新代码合进自己的工作分支：

```bash
git checkout feature/local-compat
git merge main
git push
```

这一步的目标不是拉官方，而是把“已经更新过的本地 main”同步到你自己的长期分支。

## 日常推荐顺序

后面建议固定用这套顺序：

1. 先更新 `main`
2. 再更新 `feature/local-compat`
3. 最后再继续开发或测试

完整命令版：

```bash
git checkout main
git fetch upstream
git merge upstream/main
git push origin main

git checkout feature/local-compat
git merge main
git push
```

## 开始新改动前

如果你准备继续改代码，建议从自己的功能分支开始，不要直接在 `main` 上改：

```bash
git checkout feature/local-compat
```

如果后面要拆更清楚，也可以新开分支，比如：

```bash
git checkout -b feature/doubao-compat-cleanup
```

## 遇到冲突时

如果 `git merge main` 或 `git merge upstream/main` 提示冲突：

1. 先看 `git status`
2. 打开冲突文件处理
3. 处理完后执行：

```bash
git add 冲突文件
git commit
```

如果输出里已经出现：

```bash
Merge made by the 'ort' strategy.
```

说明这次 merge 已经成功，不需要再手动 `git commit`。

## 更新前先确认工作区干净

每次同步前，先跑：

```bash
git status
```

理想情况应该是：

```bash
nothing to commit, working tree clean
```

如果不是干净状态，先提交或暂存，不要直接拉新代码。

## 如果本地有改动还没准备提交

临时存一下：

```bash
git stash push -u -m "before sync"
```

同步完成后恢复：

```bash
git stash pop
```

但如果改动已经比较大，优先建议直接提交到分支，而不是长期依赖 `stash`。

## 网络拉不下来时

如果出现类似错误：

```bash
Failed to connect to github.com port 443
```

这通常是网络问题，不是仓库坏了。

可选处理方式：

- 换网络，比如手机热点
- 打开可访问 GitHub 的代理或 VPN
- 后续改成 `SSH over 443` 再同步

网络没恢复前，不要反复执行 `git pull`，先确认连接问题。

## 当前最稳的使用原则

- `main` 负责跟官方
- `feature/local-compat` 负责保留自己的长期能力
- 文档、豆包兼容、本地实验，尽量都不要直接堆在 `main`

这样做的好处是：

- 官方更新不会轻易覆盖你自己的修改
- 你自己的兼容改动也不会和官方主线混成一团
- 真出问题时，更容易判断是官方变了，还是你自己的分支变了
