# 短篇写作工作流说明 v1

这份工作流适合当前项目拿来跑：

- `1-2 万字`
- `4-6 章`
- 单事件闭环
- 测题材、测风格、测完成度

它的目的不是孵长篇，而是：

- 看一个点子能不能独立成立
- 看一个玩法能不能快速兑现
- 看模型能不能把故事收住

所有短篇先遵守 [短篇通用底层规则提炼 v1](短篇通用底层规则提炼-v1.md)，再按本文件选择体量、题材和生成方式。

---

## 一、什么时候适合用短篇模式

适合：

- 你只想验证一个点子
- 你想快速看“这个设定有没有戏”
- 你不想一开始就跑很长
- 你想测试模型对某种风格的把握

不太适合：

- 本来就想写百万长篇
- 题材卖点严重依赖层层升级
- 需要复杂世界观逐步展开

---

## 二、短篇模式的核心思路

短篇模式只做四件事：

1. 立住主角
2. 立住玩法
3. 完成一次冲突升级
4. 给出完整结局兑现

短篇不是“长篇第一卷压缩版”，而是“一个完整故事”。

---

## 三、推荐工作流

### 第一步：先定一个核心句

先把故事压成一句话。

格式：

- 一个什么样的主角
- 遇到一个什么异常/事件
- 用一个什么离谱玩法解决
- 最后得到什么现实结果

例子：

- 一个怕鬼社畜，绑定神鬼业务系统，第一次直播给乱收香火的门神下整改，最后异常解除、赔付到账。

如果一句话都说不顺，这题材大概率还不够短篇化。

### 第二步：只留一个案件

短篇不要开第二案。

最稳的做法是：

- 一个异常对象
- 一个委托场景
- 一次处理过程
- 一个结局

### 第三步：只保留一层世界观

短篇世界观只需要回答：

- 这东西是什么
- 主角靠什么处理
- 为什么能处理

不需要回答：

- 整套势力结构
- 系统终极来源
- 中后期升级路线

### 第四步：明确结尾怎么收

短篇开写前，结尾要先有答案。

至少提前定好：

- 异常怎么被解决
- 主角得到什么现实回报
- 结尾是偏爽、偏诡、偏温情还是偏讽刺

如果结尾不先定，模型很容易写成“刚要展开更大故事就没了”。

---

## 四、推荐章节结构

最稳结构：

### 4章版

1. 生活压迫 + 异常出现
2. 主角试着介入，玩法露头
3. 冲突升级，第一次差点翻车
4. 解决异常，现实兑现，完整收尾

### 5章版

1. 生活压迫 + 异常出现
2. 调查/试探，读者看懂玩法
3. 正面对抗，局势升级
4. 破局执行，爽点兑现
5. 收尾结案，现实到账

### 6章版

1. 生活压迫 + 异常出现
2. 试探介入
3. 规则逐渐成立
4. 危机升级
5. 正式破局
6. 收尾和兑现

---

## 五、提示词怎么写最稳

短篇提示词最重要的是短，不要写成长篇版删减稿。

重点只写：

- 总字数
- 章数
- 一个案件闭环
- 风格要求
- 结尾必须兑现

不要写太多：

- 长线升级要求
- 阶段推进要求
- 多弧线结构
- 势力与终局说明

一句话总结：

短篇提示词是“收束型提示词”，不是“展开型提示词”。

---

## 六、在当前项目里的建议用法

如果用 `ainovel-cli --headless --prompt-file xxx.md` 跑短篇，建议：

1. 单独新建一个短篇 prompt 文件
2. 不要混用长篇 foundation
3. 不要让模型先做长篇规划
4. 直接让它写完整短篇正文

推荐顺序：

1. 写一句话核心句
2. 选一个短篇提示词模板
3. 直接生成正文
4. 只检查三件事：
- 有没有尽快进入冲突
- 有没有中段升级
- 有没有完整收口

---

## 七、短篇审看时最该盯什么

优先看：

1. 第一章有没有尽快进入异常
2. 第二章前有没有看懂玩法
3. 中后段有没有升级而不是原地打转
4. 结尾有没有兑现

不要太纠结：

- 复杂底盘是否完整
- 长线有没有铺够
- 后续能不能无限扩写

因为短篇本来就不靠这些赢。

---

## 八、最常见的短篇失败方式

1. 写成了长篇序章

表现：
- 铺了很多设定
- 事情刚开始就结束
- 结尾纯留坑

2. 写成了一个点子的段子扩写

表现：
- 好笑，但没升级
- 有反差，但没结果
- 读完没有完整故事感

3. 写成了说明书

表现：
- 主角一直在解释规则
- 系统一直在讲机制
- 剧情推进很少

4. 结尾收不住

表现：
- 最后临时加大设定
- 最后抛更大阴谋
- 没真正解决眼前问题

---

## 九、一句话原则

短篇模式下，最重要的不是“世界有多大”，而是：

`这一次事件，能不能完整、好看、痛快地讲完。`
